# Метаданные выгрузки PM-06

Данные, которых нет в `data/*.json`: статусы заказов и каталог всех колонок
исходной выгрузки BW-отчёта PM-M06. Собраны из 23 выгрузок ветки `rawdata`
(площадки 1100–1400, годы 2022–2027, 422 774 заказа). Страница TOPO эти
файлы не загружает, они нужны для анализа и доработки конвейера.

## Файлы

| Файл | Что внутри |
|---|---|
| `order_status/<площадка>_<год>.json` | статус каждого заказа: системный, пользовательский, вид заказа, вычисленная фаза и признак «оригинал, перенесённый копией в «Развитие»» |
| `ppm_flags/<площадка>_<год>.json` | признак ППМ компонентов («Резерв./заявка»): только исключения «Начиная с деблок.» и «Никогда» по паре заказ × № ЕКМТР; остальное — «Немедленно» |
| `build_pm06_meta.py`, `build_all.sh` | пересборка `order_status/` и `ppm_flags/` из исходных выгрузок ветки `rawdata` |
| `pm06_status_catalog.json` | все коды статусов (38 системных, 67 пользовательских): сколько заказов, годы, доля с фактом, распределение по фазам, примеры заказов, известная расшифровка |
| `pm06_fields.json` | все 61 колонка выгрузки: смысл, использует ли её TOPO, уровень, заполненность, типичные значения, ценность для анализа |

## Формат `order_status`

Площадки и годы — те же, что в `data/`: выгрузка 1200 разведена на 1200 и
2400 (Сухой Лог) по балансовой единице.

```
{
  "meta": {"site": "1200", "year": "2026", "orders": 3878, "phases": [...], ...},
  "sys":  ["<коды системного статуса через пробел, по алфавиту>", ...],
  "usr":  ["<коды пользовательского статуса>", ...],
  "kind": ["APP1", "ARP1", ...],
  "kindText": {"APP1": "ТОРО по ППР", ...},
  "pg": ["", "1100/100", "1100/200", ...],
  "pgText": {"1100/100": "Механика", ...},
  "o": {"<заказ>": [индекс в sys, индекс в usr, индекс в kind, фаза, копия-оригинал, индекс в pg], ...}
}
```

Фаза — индекс в `meta.phases`: 0 — нет статуса, 1 — `ОТКР`, 2 — `ДЕБЛ`
(или `ЧДЕБ`), 3 — `ТЗКР`, 4 — `ЗАКР`. У каждого заказа ровно один из этих
кодов: пересечений нет ни в одном из 422 774 заказов.

**Заказ закрыт, если фаза 3 (`ТЗКР`) или 4 (`ЗАКР`).** Смысл `ОТКР`,
`ДЕБЛ`, `ТЗКР` и `ЗАКР` взят из спецификации отчёта — листа «Алгоритмы
выборки» в самой выгрузке.

**Позиции без статуса (фаза 0) — не заказы и не входят в план**
(подтверждено): это позиции графика ППР 2027 года с номерами из
диапазона планов ТОРО, заказ по ним не создан. В план и потребность их
не включать.

Пары «копия АО «Развитие» + оригинал на заводе БЕ» (та же ЕО, вид работ
и дата) — копии при переносе (подтверждено). Факт берётся с обеих
сторон, неисполненный план — только с копии. Ответы на вопросы собраны в
`pm06_status_catalog.json`, поле `meta.userAnswers`.

Копия-оригинал — 1, если у заказа планирующего завода БЕ есть заказ АО
«Развитие» на ту же ЕО, вид работ и базисную дату начала. Это копия при
переносе (подтверждено): факт оригинала учитывается, неисполненный план —
нет. Поле «планирующий завод» есть только в выгрузках с 2024 года.

Группа планирования (`pg`) — колонка «Заказ Группа планирования ТОРО»,
значение «завод/группа» (`1100/100`, `7101/200`), с 2024 года; до 2024 года
пусто. Группы 100 Механика и 200 Энергетика планирует АО «Развитие» —
только они входят в оценку планирования; 300 Метрология, 400 ЗиС,
500 Пожарная охрана, 600 АГиТО, 700 Эксплуатация, 800 ГПМ, 900 КИПиА —
службы БЕ (заказчика) (подтверждено). Шестой элемент заказа может
отсутствовать в файлах, собранных раньше: читать как «группа не указана».

## Пересборка

```
pm06_meta/build_all.sh /tmp/pm06work
```

Скрипт скачивает выгрузки из `rawdata` по одной, обрабатывает и удаляет:
все 23 файла (≈700 МБ) на диске одновременно не нужны. Шаг `extract`
пишет промежуточный JSON по каждой выгрузке, шаг `assemble` собирает
`order_status/` и `ppm_flags/`. Каталог статусов
`pm06_status_catalog.json` с расшифровками ведётся отдельно.

## Проверка

Для каждого файла `data/<площадка>_<год>.json` в `main` статус найден у
100 % заказов. В `order_status` есть и заказы, которых нет в `data/`:
от 14 до 2 466 на файл. Это заказы, у которых все стоимости и количества
нулевые, — конвейер отбрасывает такие строки (`isZeroRow`).

## Расшифровки статусов

Смысл кодов взят из документации SAP в `rawdata/SAP_Description`: КД
ERP.13.9.2.52 (табл. 16–24 — статусные схемы и виды заказов), памяток
ТОиР-66, 75, 77, 84, 86, 96 и скриншота окна статусов SAP. У каждого кода
в `pm06_status_catalog.json` есть поля `sapText`, `meaning`, `source` и
`confidence`. 96 из 105 кодов подтверждены документацией, окном статусов SAP или
заполненным файлом `Order_status_codes.xlsx`. Не расшифрованы ОБСЗ и АРВО
(заказы ТОРО) и 5 кодов сетевых графиков и вспомогательного производства;
на правило «закрыт или нет» они не влияют.

Цепочка закрытия заказа АО «Развитие» (`meta.closureChain`):
ДЕБЛ → ПДТВ/ЧПДТ, ПРНТ → ФХСМ → ТЗКР → ПРСЗ | НПСЗ → ВСБЕ → ЗАКР.

Цепочка согласования (`meta.ordinalRule`): ПЛАН → СГПЛ → ССПЛ → СГГС,
в любой момент активен ровно один из этих статусов.

Подробный разбор с проверками и цифрами — `PM06_STATUSES.md` в
репозитории TZ, ветка `claude/provision-year-status-and-render-speed`.
